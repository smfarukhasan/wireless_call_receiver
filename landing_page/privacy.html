Privacy Policy

How Wireless Call Receiver accesses and processes information on your Android device.

Effective: August 29, 2026 · Last updated: August 29, 2026

1. Scope and contact

This policy applies to the Wireless Call Receiver Android application. Wireless Call Receiver is an accessibility tool designed primarily to help blind and visually impaired users answer or end supported cellular and internet calls using configured Bluetooth hardware controls.

Contact the project maintainer through the support page or GitHub Issues. Do not include sensitive personal information in a public issue.

2. Information accessed on your device

The app processes only information needed for capabilities you choose to enable:

  • Bluetooth connection information: whether a paired Bluetooth audio device is connected and its device name or alias.
  • Call notification information: the originating package name, notification category, call-action labels, and temporary Android action tokens for supported calling apps.
  • Supported call-interface information: visible text, content descriptions, view identifiers, and window structure used to locate an Answer or End Call control.
  • Hardware-control events: configured headset, media, call, or volume key events used to trigger call controls.
  • Local settings: language, master-service state, screen-state choices, and auto-answer preferences.

The app does not request or access contacts, Call Log, SMS, location, microphone recordings, camera content, photos, videos, documents, advertising identifiers, or account credentials.

3. How information is used

On-device processing detects a connected headset and a supported incoming or active call, then invokes a native call action or performs a targeted accessibility click or tap. Cellular call answering can use Android Telecom when Answer Phone Calls permission is granted. Deterministic auto-answer occurs only after the user explicitly enables that setting.

Accessibility window inspection is restricted to supported phone and internet-calling packages included by the app. Notification processing is disabled while the Master Service is off.

4. Collection, transmission, and sharing

The developer does not collect, sell, rent, share, or transmit personal or sensitive user data.

Wireless Call Receiver does not declare Android Internet permission and includes no advertising or analytics SDK. Call information and temporary action tokens are processed in memory and are not sent to developer-controlled servers. Diagnostic logs avoid notification action text and call-interface text.

5. Permissions and sensitive APIs

  • Nearby Bluetooth Devices: connection state and connected device name.
  • App Notifications: the user-visible foreground monitoring notification.
  • Answer Phone Calls: Android Telecom cellular call-answer fallback. No Call Log permission is requested.
  • AccessibilityService: supported call notifications and interfaces, configured hardware controls, and narrow answer or end-call actions.
  • Notification Listener: supported call-style notifications and native call actions.
  • Connected-device foreground service: user-visible Bluetooth call-control monitoring while enabled.

Each runtime permission is requested separately. Accessibility and Notification Access each have a standalone disclosure with Agree and Continue and Not Now choices before Android Settings opens. All access can be revoked in Android Settings.

6. Storage, backup, retention, and deletion

Preferences are stored in Android private app storage. Depending on device backup settings, preferences may be included in an Android system backup or device transfer; the developer does not receive or control those backups. Temporary call information is retained only while needed for the current call state.

Wireless Call Receiver creates no user account and the developer holds no user data. Delete local data through Android Settings → Apps → Wireless Call Receiver → Storage → Clear data, or uninstall the app.

7. Security

Android protects binding to the Accessibility and Notification Listener services with system permissions. The app minimizes processing to supported calling packages and keeps sensitive processing on the device. No software can be guaranteed completely error-free, but access and retention are deliberately minimized.

8. Children's privacy

The app is not specifically directed to children under 13 and does not knowingly collect children's personal data. Its primary audience is users who need accessibility call-control functionality.

9. Changes

Material changes will be posted on this public page with a revised effective or last-updated date. This policy URL is intended to remain active and publicly accessible.

10. Contact

Use the Wireless Call Receiver support page or GitHub Issues. Do not post phone numbers, notification content, or other sensitive information in a public issue.
